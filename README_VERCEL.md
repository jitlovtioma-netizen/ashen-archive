# Деплой «Архива Пепельной Длани» на Git + Supabase + Vercel

Этот гайд — как поднять сайт на связке **GitHub (Git) + Supabase (база) + Vercel (хостинг)**,
и что для этого уже подготовлено в коде.

> Для самостоятельного хостинга (VPS + SQLite) есть отдельный [README_DEPLOY.md](README_DEPLOY.md).

## 🚀 Обновление до v5.7 (Ирис не отпускает: стадии 5–6, эхо карточек)

Схема БД НЕ менялась — `db:push` НЕ нужен. `db:seed` обязателен:

```bash
bun install
bun run db:seed   # MERGE: ачивка IRIS_BOUND (станет 11 достижений)
git push           # Vercel пересоберёт сам
```

**Что нового в v5.7:**
- **Стадии 5–6 «ИРИС НЕ ОТПУСКАЕТ»**: 6–7-е открытия растворяют до
  ~78% чистых слов; прибор переименован, счётчик «∞», рамка модалки
  дышит чаще (двойное кольцо + виньетка).
- **Заголовок досье тает**: на стадиях 5+ имя записи переливается
  градиентом (на 6-й — «дышит» расфокусировкой).
- **Ирис-эхо на карточках**: наведение на ирис-досье в списке —
  тихий ответ из-под страницы (10 фраз, средняя полоса экрана).
- **Превью карточки растворяется** по стадии; чип: «ꙮ ПОГЛОЩЕНИЕ» →
  «ꙮ РАСТВОРЕНО» → «ꙮ ИРИС НЕ ОТПУСКАЕТ».
- **Встреча стадии 5+**: ирис не здоровается — 8 жёстких фраз.
- **Достижение «ꙮ Он Не Отпускает» (IRIS_BOUND, оба мира)** —
  восьмое открытие поглощённого досье.
- **«Ирис в цифрах» в Мастерской**: агрегация поглощения по всем
  стражам (открытия, читатели, съеденные слова, топ-8 досье).

Схема БД МЕНЯЛАСЬ — в этот раз `db:push` **ОБЯЗАТЕЛЕН** (безопасно:
новая колонка с дефолтом, данные не теряются). Один раз после `git pull`:


**Что нового в v5.6:**
- **«Ирис поглощает»**: каждое повторное открытие ирис-досье (⟪…⟫)
  кормит ирис — со второго раза чистые слова текста растворяются
  в переливающихся глифах. Стадии 0..4, до ~55% текста проглочено.
- **Прибор «ПОГЛОЩЕНИЕ»** в досье: ꙮ + 5 наливающихся сегментов +
  счётчик N/5 + подсказка стадии («ирис тянется к словам»…).
- **Чип на карточке**: «ꙮ ПОГЛОЩЕНИЕ N/5», с пятого открытия —
  «ꙮ РАСТВОРЕНО».
- **Прощальный ирис-шёпот** при закрытии досье (12 фраз, нижняя
  половина экрана).
- **Достижение «ꙮ Глазами Ириса» (IRIS_DEVOTED, оба мира)**: открыть
  ирис-досье пять раз — пока было что открывать.
- **Тост «ИРИС ПРОЧИТАН X ИЗ Y»** при новом прочитанном ирис-досье
  (когда в мире их больше одного) + мини-бар в Профиле.

  открытии записи черновик вернётся (тост «ЧЕРНОВИК ВОССТАНОВЛЕН»,
  кнопка «⌫ СБРОС» откатывает к сохранённой версии).
- «● ИЗМЕНЕНО» — пульсирующий индикатор несохранённых правок; вкладка с
  правками попросит подтверждение перед закрытием.
- Sticky-панель действий в форме: СОХРАНИТЬ/ОТМЕНА/СБРОС всегда под рукой
  (прилипает к низу экрана при прокрутке длинной формы).
- Поле «ПОРЯДОК СОРТИРОВКИ» теперь есть и у героев/локаций (ручной ввод

## 🚨 Быстрый фикс: «Не удалось получить данные http 500» на всех разделах

**Симптом:** сайт открывается, интерфейс живёт, но герои/лор/профиль пустые,
везде ошибка HTTP 500. Часто появляется после загрузки в git файлов из
старого seed.zip (до v4.3.2).

**Причина №1 (99% случаев): в `prisma/schema.prisma` стоял `provider = "sqlite"`
при postgres-ссылке в `DATABASE_URL`.** На Vercel база — Supabase PostgreSQL;
Prisma-клиент, собранный под SQLite, не может открыть postgres-ссылку → каждый
запрос в БД падает.

**Начиная с v4.3.2 это невозможно в принципе:** скрипт
`scripts/sync-db-provider.mjs` читает `DATABASE_URL` и сам ставит правильный
provider. Он запускается автоматически из `postinstall`, `dev` и `build` —
на Vercel при деплое, на своём сервере при `bun install` / `bun run dev`.
Если задан `DIRECT_URL`, в схему добавляется `directUrl` (нужен для
`prisma db push` / сида мимо pooler'а); не задан — строка убирается.

**Что сделать на старой версии (фикс за 1 минуту, прямо на GitHub):**
1. Обнови файлы до v4.3.2+ (залей свежий seed.zip в репозиторий) — и всё,
   дальше провайдер подстраивается сам.
2. Либо вручную: `prisma/schema.prisma` → Edit →
   ```diff
   - provider = "sqlite"
   + provider = "postgresql"
   ```
   → Commit → Vercel пересоберёт сам.

**Причина №2: не задана/неверна `DATABASE_URL`.**
Vercel → Settings → Environment Variables:
`DATABASE_URL` = Supabase **transaction pooler** (порт 6543) с параметрами
`?pgbouncer=true&connection_limit=1`. После смены — Redeploy.

**Причина №3: в Supabase нет таблиц** (новый проект).
Локально: в `.env` — direct-ссылка (5432), затем
`bunx prisma db push && bun run db:seed && bun run prisma/bind-characters.ts`
(подробно — шаг 2 ниже).

## Шаг 1. Создай проект Supabase

1. [supabase.com](https://supabase.com) → **New project**.
2. Придумай пароль БД (database password) — сохрани его.
3. Регион выбери ближе к игрокам (например, Frankfurt).
4. Когда проект создастся, открой **Project Settings → Database**. Оттуда нужны
   две строки подключения (кнопка **Connection string**):

**Direct connection** (порт 5432) — для залива таблиц и данных с твоей машины:
```
postgresql://postgres:ПАРОЛЬ@db.ПРОЕКТ_REF.supabase.co:5432/postgres
```

**Transaction pooler** (порт 6543) — для рантайма на Vercel:
```
postgresql://postgres.ПРОЕКТ_REF:ПАРОЛЬ@aws-0-РЕГИОН.pooler.supabase.com:6543/postgres?pgbouncer=true&connection_limit=1
```
> Параметр `?pgbouncer=true&connection_limit=1` обязателен: serverless-функции
> Vercel открывают много коротких соединений, без пулера упрёшься в лимит Supabase.

## Шаг 2. Залей базу архива в Supabase (один раз, с твоей машины)

В папке проекта локально:

```bash
# 1. Установи зависимости
bun install

# 2. Убедись, что Prisma настроен на PostgreSQL.
#    В свежем seed.zip схема УЖЕ postgresql — команда ниже только для
#    старых версий архива (когда в схеме было sqlite):
bun run db:use-postgres   # или проверь: grep provider prisma/schema.prisma

# 3. В .env поставь DIRECT-ссылку (порт 5432) из Шага 1
#    DATABASE_URL=postgresql://postgres:ПАРОЛЬ@db.ПРОЕКТ_REF.supabase.co:5432/postgres

# 4. Создай таблицы в Supabase
bunx prisma db push

# 5. Залей данные архива: аккаунты, героев, лор, богов, локации, хроники
bun run db:seed

# 6. Примени привязки персонажей к аккаунтам
bun run prisma/bind-characters.ts

# 7. Пересобери Prisma-клиент под postgres
bunx prisma generate
```

Проверка: в Supabase → **Table Editor** должны появиться таблицы `User`,
`Character`, `Lore`, `Progress`… с данными.

## Шаг 3. Залей код в Git

```bash
git add prisma/schema.prisma
git commit -m "postgres provider для Supabase/Vercel"
git push
```

Важно:
- **`schema.prisma` с `provider = "postgresql"` должен быть в git** — по нему
  Vercel сгенерирует правильный клиент при сборке (`postinstall: prisma generate`
  уже прописан в package.json).
- `.env` в git не входит (.gitignore) — пароли не утекут.
- Вернуться на локальную SQLite можно в любой момент: `bun run db:use-sqlite`.

## Шаг 4. Подключи Vercel

1. [vercel.com](https://vercel.com) → **Add New… → Project** → импортируй свой
   Git-репозиторий.
2. Framework Preset определится как **Next.js**. Настройки сборки можно не
   трогать (`postinstall` сам синхронизирует prisma-провайдера и соберёт
   клиент). Для гарантии (v4.3.6+) поставь в **Settings → General →
   Build Command**: `bun run build` — тогда перед `next build` всегда
   прогоняются проверка зависимостей и авто-синк провайдера из
   package.json, независимо от того, выполнился ли postinstall.
3. **Environment Variables** добавь:

   | Имя | Значение |
   |---|---|
   | `DATABASE_URL` | **Transaction pooler**-ссылка (порт 6543, с `?pgbouncer=true&connection_limit=1`) из Шага 1 |

4. Жми **Deploy**. Через пару минут сайт живой на `твой-проект.vercel.app`.

Проверка: открой сайт, войти как `dnd` / `ashen` — должны подгрузиться герои,
лор и профиль. Если 500 — почти всегда неверный `DATABASE_URL` (взят порт 5432
вместо 6543 или забыт `pgbouncer=true`).

## Шаг 5. Картинки

**Вариант 1 (простой): лежат в репозитории.** Папка `public/heroes`, `public/gods`,
`public/videos` коммитится в git и раздаётся Vercel'ом как статика. Ничего делать
не надо. Бесплатный лимит Vercel Hobby — ~100 ГБ трафика/мес, для партии хватит.

**Вариант 2 (Supabase Storage):**
1. Supabase → Storage → создай **public**-бакет с именем `images`.
2. Locally в `.env` добавь `NEXT_PUBLIC_SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`
   (Settings → API), затем `bun run upload-images` — скрипт зальёт все портреты.
3. В Vercel добавь env `NEXT_PUBLIC_SUPABASE_URL` — картинки начнут браться из
   `${SUPABASE_URL}/storage/v1/object/public/images/...`.

> Замена конкретного портрета: просто перезаписи файл в `public/heroes/…`
> (вариант 1) или в Storage (вариант 2) — имя файла не меняй.

## Шаг 6 (опционально). Онлайн-стражи

Сайт **полностью работает без этого шага**: без presence просто не показывается
«кто в сети»; статус-бар честно пишет «ОФЛАЙН».

Есть **два режима**, включаются переменными окружения (можно ничего не ставить —
тогда всё выключено):

| Режим | Что даёт | Что нужно |
|---|---|---|
| **Supabase Realtime (БЕСПЛАТНО)** | кто онлайн прямо сейчас + «в архиве с…» + «был в сети: время» | твой же Supabase-проект, 2 env-переменные |
| socket.io-сервис | всё то же + **админ-вещание на весь экран и изгнание** | отдельный долгоживущий процесс (Railway/Render/Fly/Koyeb) |

### Вариант А — БЕСПЛАТНО, на твоём же Supabase (5 минут, без новых сервисов)

Supabase Realtime — это встроенные в твой проект websocket-каналы. Браузер
стражей соединяется с ними напрямую, Vercel остаётся только сайтом. Входит в
бесплатный тариф (лимитов с головой хватит на партию: ~200 одновременных
соединений, 2 млн сообщений/мес).

1. **Один раз** после обновления кода до v4.5+ выполни миграцию колонки
   «был в сети» (nullable, без потерь данных):

   ```
   bun run db:push
   ```

   (это добавит `User.lastSeenAt`; прогресс и данные не трогаются)

2. Supabase Dashboard → **Project Settings → API** → скопируй ключ
   **`anon public`** (он публичный по дизайну, это не секрет).

3. В Vercel добавь две переменные (если `NEXT_PUBLIC_SUPABASE_URL` уже есть —
   остаётся только вторая):

   | Имя | Значение |
   |---|---|
   | `NEXT_PUBLIC_SUPABASE_URL` | `https://xxxx.supabase.co` (уже есть для картинок) |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | `eyJ...` (ключ anon public) |

   ВАЖНО: убери `NEXT_PUBLIC_PRESENCE_URL`, если задавал её раньше —
   socket.io-режим имеет приоритет и перекроет бесплатный.

4. **Redeploy** (публичные переменные вшиваются в сборку клиента).

5. Проверка: открой сайт в двух вкладках под разными логинами — в профиле
   у обоих горит «В СЕТИ», «в архиве с …», а у оффлайн-стражей со временем
   появляется «⚑ был в сети: N мин назад». «Был в сети» пишется в основную
   БД (heartbeat раз в минуту) и переживает любые перезапуски.

> Что НЕ работает в этом режиме: админ-вещание на весь экран и изгнание
> стража (это фичи socket.io-сервиса). Если они не нужны — всё, готово.

### Вариант Б — socket.io-сервис (вещание + изгнание)

**Почему не на Vercel:** это долгоживущий websocket-процесс (socket.io).
Vercel — serverless: функции живут секунды и не держат открытые соединения.
Поэтому сервис хостится ОТДЕЛЬНО на платформе с постоянным процессом:
Railway (проще всего, но по сути платный после триала), Render, Fly.io,
Koyeb.

Рецепт для Railway (5 минут):
1. Залей папку `mini-services/presence-service` в отдельный Git-репозиторий
   (или отдельную ветку/папку — Railway умеет root directory).
2. railway.app → **New Project → Deploy from GitHub repo**, root directory =
   `mini-services/presence-service`.
3. Build Command: `bun install && bunx prisma generate`
   Start Command: `bun index.ts`
   (в репозитории схема сервиса — postgresql, как и основная).
4. Variables (Settings → Variables):

   | Имя | Значение |
   |---|---|
   | `PRESENCE_DB_URL` | Supabase transaction pooler (порт 6543, с `?pgbouncer=true&connection_limit=1&sslmode=require`) |
   | `PORT` | Railway подставляет сам — сервис слушает `process.env.PORT ?? 3003` |

5. Railway выдаст публичный HTTPS-домен (например `presence-xxxx.up.railway.app`).
6. В Vercel добавь env: `NEXT_PUBLIC_PRESENCE_URL=https://presence-xxxx.up.railway.app`
   и сделай **Redeploy** (переменная вшивается в сборку — без редеплоя не подхватится).
7. Проверка: открой сайт в двух вкладках под разными логинами — в профиле
   у обоих горит «В СЕТИ», у админа появляются кнопки вещания и изгнания.

> CORS на сервисе уже открыт — сокет ходит напрямую с домена Vercel на домен
> сервиса. `lastseen` переживает рестарты сервиса (файл рядом с ним).
> Render/Fly аналогично: постоянный процесс + публичный HTTPS + те же переменные.

## Шаг 7 (после обновления на v4.6). Новые осколки богов — одна команда

В v4.6 появились три осколка памяти PF2E: Асмодей («Осколок Контракта»),
Фаразма («Осколок Смерти») и Ароден («Осколок Надежды»), а вкладка
«Секреты» Голариона теперь открывается после **5** собранных осколков
(шестой остаётся бонусом). Схема БД не менялась — `db:push` не нужен.

На своей машине, в папке проекта, с прод-`.env` (DATABASE_URL на Supabase,
подойдёт и pooler-ссылка):

```bash
git pull
bun install
bun run db:add-pf2e-shards
```

Скрипт идемпотентный: находит записи по названиям («Асмодей», «Фаразма»,
«Ароден — Бог Человечества»), ставит им shardWord и печатает итоговый
список осколков. Повторный запуск ничего не ломает. Затем просто задеплой
как обычно (git push → Vercel пересоберёт сам).

**Кто и что может редактировать в досье (v4.6):** страж, к которому привязан
персонаж (например, GTT_EDMI → Каэль Валькрейн), правит описание/эпитет/статус
своего досье — правки видны всем. Админ (Созидатель) может править любое
досье. Изменений схемы для этого не требуется.

## Частые вопросы

**Обязательно ли Supabase для картинок?** — Нет. Достаточно `public/` в git.

**Прогресс игроков сохранится при передеплое?** — Да, он в таблице `Progress`
в Supabase, а не на сервере Vercel.

**Можно ли оставить SQLite и не использовать Supabase?** — На Vercel нет:
там файловая система read-only, файл базы нельзя открыть на запись.
SQLite — только для своего сервера (README_DEPLOY.md).

**Vercel пишет "P1001: Can't reach database"?** — Проверь `DATABASE_URL`:
на Vercel нужен **pooler** (порт 6543) с `?pgbouncer=true`, а не прямой 5432.

**Хочу вернуть разработку локально на SQLite.** — `bun run db:use-sqlite`,
в `.env` верни `DATABASE_URL=file:...`, затем `bunx prisma generate`.

**Безопасность.** — Пароли в БД лежат открытым текстом (осознанный выбор для
настольной партии). Не переиспользуй пароль Supabase где-то ещё и не выкладывай
`seed.zip` на боевой сайт — внутри пароли аккаунтов. С v5.7.1 архив и не
попадёт туда случайно: он собирается в `seed-archive/` (gitignored) и
раздаётся только по подписанным 15-минутным ссылкам через `/api/seed`.
