⚗ v4.3.2: ПРОВАЙДЕР БД ВЫСТАВЛЯЕТСЯ САМ.
  Скрипт scripts/sync-db-provider.mjs запускается автоматически при
  bun install / npm install / bun run dev / build, читает DATABASE_URL
  и сам ставит правильный provider в prisma/schema.prisma:
    postgresql://… (Supabase)  → provider = "postgresql"
    file:…        (SQLite)      → provider = "sqlite"
  Ошибка «Не удалось получить данные http 500» из-за рассинхрона
  провайдера (причина инцидента на v4.3) теперь невозможна в принципе.

Твой сайт хостится на Vercel + Supabase (файлы заливаются в Git)?
  -> Просто закинь файлы из этого архива в репозиторий и запушь.
  -> Ничего переключать руками не нужно: при деплое Vercel выполнит
     install, провайдер подстроится под DATABASE_URL сам.
  -> Проверь на Vercel: Settings -> Environment Variables:
     DATABASE_URL = Supabase pooler-ссылка (порт 6543) с параметрами
     ?pgbouncer=true&connection_limit=1
     (опционально DIRECT_URL = порт 5432 — для prisma db push / сида)
  -> Подробная инструкция: README_VERCEL.md

Хочешь запустить на СВОЁМ сервере с локальной базой (SQLite)?
  -> Ничего переключать руками не нужно: создай .env со ссылкой
     DATABASE_URL=file:/абс/путь/db/custom.db — провайдер подстроится
     сам при запуске. Дальше действуй по README_DEPLOY.md (5 минут).

Важно:
  * .env в архиве НЕТ (он в .gitignore) — создай свой по .env.example.
  * db/custom.db — готовая SQLite-база со всеми данными и прогрессом.
    На Vercel она НЕ используется (данные живут в Supabase) — это бэкап
    и данные для локального запуска.
  * В сидe пароли аккаунтов открытым текстом — не выкладывай
    public/seed.zip на боевой сайт.

Если на Vercel все разделы выдают «Не удалось получить данные http 500»:
  открой https://твой-сайт.vercel.app/api/stats?system=DND — в ответе
  будет готовая подсказка (hint), что именно не так. См. также
  README_VERCEL.md, секция «Быстрый фикс» в самом верху.
